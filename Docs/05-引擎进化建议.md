# 引擎升级与进化建议清单

> 基于 2026-08-15 全库代码审查。按"投入产出比"分组，
> P0 = 立即做，P1 = 近期做，P2 = 方向性投入。

## P0 —— 工程健康（低成本高收益）

1. **统一源码编码**：`Scene.cpp/Scene.h` 等文件是 UTF-16(BOM) + GBK 注释，
   其余是 UTF-8。混合编码使 grep/评审工具/blame 全部失效。
   建议一次性转换为 UTF-8 with BOM（MSVC 兼容），并加 `.editorconfig` 锁定。
2. **启用断言**：确认 Debug 配置定义 `CD_ENABLE_ASSERTS`；
   本次修复的很多崩溃如果断言开着，会在开发期第一时间暴露。
3. **崩溃转储**：集成 `SetUnhandledExceptionFilter` + `MiniDumpWriteDump`，
   编辑器崩溃自动写 `.dmp`，配合 PDB 可精确定位（比 try/catch 有效得多）。
4. **CI**：迁移 CMake（见 02 号文档）后接 GitHub Actions：
   Windows 构建 + shader 编译冒烟测试。
5. **拼写与注释治理**：`rezize`、`Stafe`、乱码注释（GBK 在 UTF-8 下显示）
   等，建议过一遍 clang-tidy + 拼写检查。

## P1 —— 架构补强（中期）

6. **资产系统（AssetManager）**
   - 现状：资源按文件路径裸引用（`Texture2D::Create("assets/...")` 散落各处）。
   - 建议：Asset 句柄（UUID）+ 资产注册表 + 引用计数；编辑器 ContentBrowser
     已是雏形，把它升级为资产数据库（.cdasset 元数据文件）。
   - 收益：热重载、打包部署、资产依赖追踪的地基。
7. **着色器系统**
   - 热重载（filewatch 已在 vendor，接 ShaderLibrary 即可）。
   - 用 SPIRV-Cross 反射替代手写 uniform 上传，消灭 `SetMat4("u_xxx")` 字符串调用。
   - 缓存带哈希已修复（见 01 号文档），下一步把缓存目录纳入版本管理忽略
     并支持一键清空菜单项。
8. **场景序列化版本号**：SceneSerializer 写入 `version` 字段，
   未来组件格式变更时可做迁移而不是直接加载失败。
9. **ECS 升级评估**：当前 entt 单头较旧（view/group API 是老风格）。
   升级 entt 到 3.13+ 可获得 `storage` 稳定性保证、更好的性能和
   `entt::snapshot` 网络同步潜质。
10. **日志异步化**：spdlog 支持 async logger，编辑器日志量大时（每帧 trace）
    能明显降低主线程开销；同时加日志级别运行时开关面板。

## P2 —— 能力进化（方向性）

11. **渲染线程/渲染命令队列**：把 GL 调用收敛到渲染线程，主线程只提交命令。
    是帧率上限的最大杠杆，也为 Vulkan 迁移铺路（Vulkan 必须多线程录制）。
12. **Job System**：简单的 work-stealing 线程池，先服务资产异步加载与
    C# 脚本次要逻辑。
13. **内存剖析**：`CD_PROFILE` 已有 Instrumentor（Chrome tracing），
    补一个分配器层的内存追踪（重载 new/delete 计数 + 分类统计）。
14. **单元测试**：用 doctest/catch2 先覆盖 Math、Scene 序列化、UUID、
    事件分发这些无 GL 依赖的纯逻辑。
15. **平台抽象收尾**：`Platform/Windows` 之外保留接口整洁性，
    Input/Window/FileDialogs 都已有抽象，保持住，别在 Editor 里直接调 Win32。
16. **3D 升级**：见 04 号文档（五阶段计划）。
17. **编辑器体验**
    - 撤销/重做（Command 模式，序列化 diff 即可实现）。
    - 场景多开/预制体（Prefab = 子场景 + 覆盖记录）。
    - Play 模式下的"运行时修改保留"选项。
18. **性能面板**：把 Instrumentor 数据在编辑器内可视化（帧时历史、
    各系统耗时条形图），不必每次都导出 Chrome tracing。
