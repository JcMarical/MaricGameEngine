# 2D → 3D 引擎升级改造计划

> 现状：CryDust 是纯 2D 渲染（Renderer2D 批渲染 quad/circle/line/text），
> 但底座已经具备不少 3D 前置条件：glm 数学库、`EditorCamera`（透视投影 +
> 轨道控制）、`SceneCamera` 已有 Perspective 模式、ImGuizmo 3D 变换 gizmo、
> 实体 ID 拾取缓冲、UBO + SPIR-V 管线。
> 本计划按"先抽象、再打通、后丰富"分五个阶段，每阶段结束都有可演示成果。

## 阶段 0：渲染抽象层加固（1~2 周）

3D 的所有工作都建立在干净的渲染抽象上，先还债：

1. **消除渲染 API 直接依赖**
   - `CryDust/Scene` 与 `CryDust-Editor` 中不得 include `Platform/OpenGL/*`，
     `glad.h` 只允许出现在 Platform 层。
   - `FramebufferTextureFormat` 增加 `RED_INTEGER` 之外的通用格式
     （`RGBA16F`、`RGBA32F`、`DEPTH32F`），为 HDR 与 3D 深度做准备。
2. **RenderCommand/RendererAPI 补齐 3D 能力**
   - 深度测试开关/函数、面剔除、混合模式、视口、polygon mode。
   - `DrawIndexed` 之外补 `DrawArrays`、`DrawIndexedInstanced`。
3. **Shader 系统改造**
   - 每 pass 多输出（MRT）与 uniform/SSBO 绑定的显式接口。
   - 借助 SPIRV-Cross 做反射，自动生成 uniform 布局（替代手写 SetMat4 调用）。
   - 产出：`ShaderLibrary` 热重载（filewatch 已在 vendor 里，接上即可）。

**验收**：Sandbox 与编辑器行为完全不变，`Renderer2D` 全部走新抽象。

## 阶段 1：最小 3D 渲染闭环（2~3 周）

目标：编辑器里能渲染一个带贴图、可拾取、可用 gizmo 拖动的立方体。

1. **Mesh 与顶点格式**
   - `Vertex`（Position/Normal/UV/Tangent），`Mesh`（VB+IB+子网格），
     `MeshFactory`（Cube/Sphere/Plane/Capsule 程序化生成）。
   - `StaticMeshComponent` + `MeshRendererComponent`（或合并为 `MeshComponent`）。
2. **Renderer3D（前向着色）**
   - 独立 `Renderer3D`，与 Renderer2D 并存（2D UI/文字继续走 2D 管线）。
   - Phong 光照起步：方向光 + 点光源组件；`LightComponent`。
   - 相机 UBO 复用现有 binding 0，新增 Model 矩阵 push/uniform。
3. **资源加载**
   - assimp 接入（vendor 新增），`.obj/.fbx/.gltf` → Mesh；纹理沿用 Texture2D，
     增加 `SRGB` 格式标记。
4. **编辑器**
   - 场景视口 3D 导航已有（EditorCamera）；层级面板加"创建 Cube/Plane/Light"。
   - 拾取缓冲继续用 RED_INTEGER 方案，3D 下天然兼容。
   - SceneSerializer 增加新组件的 YAML 序列化。

**验收**：新建场景 → 拖入 gltf 模型 → 方向光照明 → Play 模式相机环绕。

## 阶段 2：PBR 材质与阴影（3~4 周）

1. **材质系统**：`Material`（shader + uniform 值 + 纹理槽），
   `MaterialInstance` 支持覆盖；编辑器材质面板。
2. **PBR 管线**：Cook-Torrance GGX，metallic-roughness 工作流；
   IBL（irradiance + prefiltered envmap + BRDF LUT），HDR 帧缓冲（RGBA16F）
   + ACES tonemap 后处理。
3. **阴影**：方向光 CSM（2~4 级联）或先做单级联 shadow map；
   点光源 cubemap 阴影可延后。
4. **法线贴图**：切线计算（assimp 或 mikktspace）。

**验收**：标准 PBR 球阵（金属度/粗糙度渐变）+ IBL + 动态阴影截图级效果。

## 阶段 3：3D 场景系统与性能（2~3 周）

1. **空间划分与剔除**：视锥剔除（先做 per-entity AABB），再上 BVH/八叉树。
2. **实例化渲染**：相同 Mesh+Material 合并 instanced draw。
3. **天空盒/大气**：cubemap skybox 起步。
4. **3D 物理**：Box2D 只解决 2D。评估 **Jolt Physics**（推荐，现代、活跃、
   性能优于 Bullet）或 Bullet；`Rigidbody3DComponent`/`BoxCollider3DComponent`。
5. **脚本层**：C# ScriptCore 暴露 3D 组件与物理 API。

**验收**：1000 个实例化箱体物理下落 + 视锥剔除后 drawcall 稳定。

## 阶段 4：编辑器 3D 化收尾（2 周）

1. 视口网格地面、世界坐标轴、选中高亮（outline pass）。
2. 地形/植被等高级需求按游戏类型决定（本计划不含）。
3. 资产管线：`--import` 命令行（模型→二进制 mesh、纹理压缩），
   呼应 KlayGE 借鉴文档的离线工具链思想。
4. 文档与示例场景库。

## 里程碑总览

| 里程碑 | 内容 | 周期 | 风险 |
|---|---|---|---|
| M0 | 渲染抽象加固 + shader 热重载 | 1~2 周 | 低 |
| M1 | 最小 3D 闭环（mesh+前向+光照+拾取+gizmo） | 2~3 周 | 中（assimp 集成） |
| M2 | PBR + IBL + 阴影 | 3~4 周 | 中高（IBL 烘焙工具） |
| M3 | 剔除/实例化/3D 物理 | 2~3 周 | 中 |
| M4 | 编辑器 3D 化 + 资产管线 | 2 周 | 低 |

## 关键决策点（建议尽早拍板）

1. **渲染 API 路线**：继续 OpenGL 4.5（省事，够用）还是同步引入 Vulkan
   （抽象好后并行做）？建议先 OpenGL 把 3D 功能做全，Vulkan 作为独立项目。
2. **前向 vs 延迟**：中小规模 3D 场景 + 大量 2D 混合，建议 **Forward+**
   （ tiled light culling 计算着色器），比全延迟简单且 MSAA 友好。
3. **物理引擎**：Jolt > Bullet > PhysX（许可证与包体积考量）。
4. **模型格式**：运行时只读 glTF 2.0（生态最好），fbx/obj 由导入器转。
